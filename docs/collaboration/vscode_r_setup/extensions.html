Extensions

Every VS Code extension in my R and R-Lecturer profiles, what it is for, and how to install the set.
Modified

November 8, 2026

In VS Code, extensions belong to a profile: each profile has its own set. Settings Sync carries the lists between machines together with the rest of the profile (see Profiles and Settings Sync).

I use two profiles:

  • R is my daily profile: analysis, R packages, Quarto websites and everything else. It has 73 extensions.
  • R-Lecturer mirrors what students see in my courses (light theme, Material icons, %>% as the pipe shortcut). It has 65 extensions.

Together that is 86 extensions: 52 in both profiles, 21 only in R and 13 only in R-Lecturer. The “In profile” column in the tables below says which.

Ids are written in lower case, as code --list-extensions prints them. VS Code ignores the case of ids.

Minimum for R

Start here. These six are enough for R scripts, R packages and Quarto documents. Everything else on this page is optional.

  • reditorsupport.r: the R extension (console, help, plots, workspace viewer).
  • reditorsupport.r-syntax: R syntax highlighting (installed together with the R extension).
  • rdebugger.r-debugger: the R debugger.
  • posit.air-vscode: Air, the R formatter and language server by Posit.
  • quarto.quarto: Quarto rendering, preview and editing.
  • ryuta46.multi-command: needed for the chunk commands in multiCommand.commands.

The R side (R itself, radian and R packages such as languageserver, httpgd and vscDebugger) is covered in Installation.

Overlaps and clean-up candidates

Extensions that do the same job twice, or that seem to be left over. These are candidates to check, not decisions.

  • Icon themes. vscode-icons-team.vscode-icons is the active theme in R (and Default), pkief.material-icon-theme in R-Lecturer (workbench.iconTheme). R has both installed but uses one. pkief.material-product-icons in R-Lecturer is installed but not selected.
  • Docker. docker.docker, ms-azuretools.vscode-docker and ms-azuretools.vscode-containers are all in R. Container Tools has taken over the Docker extension, which now depends on it. Docker DX adds Dockerfile and Compose editing on top. Dev Containers works without any of them, as long as Docker itself is installed.
  • CSV. mechatroner.rainbow-csv, repreng.csv and phplasma.csv-to-table in R; mechatroner.rainbow-csv and grapecity.gc-excelviewer (which also opens CSV) in R-Lecturer.
  • SQLite. alexcvzz.vscode-sqlite, qwtel.sqlite-viewer and, in R-Lecturer, mtxr.sqltools-driver-sqlite all open SQLite databases.
  • TODO comments. gruntfuggly.todo-tree and wayou.vscode-todo-highlight. Todo Tree highlights the tags as well.
  • DBML. matt-meyers.vscode-dbml is marked deprecated by its author. nicolas-liger.dbml-viewer is the other DBML extension.
  • AI assistants. R has github.copilot-chat, anthropic.claude-code, openai.chatgpt (with openai.codex-audio), continue.continue and coderabbit.coderabbit-vscode. They do not conflict, but each adds a view, a sign-in and background work.
  • R Markdown. tianyishi.rmarkdown sits next to reditorsupport.r, which already handles .Rmd files (chunks, knitting), and quarto.quarto, which renders them too. It may still matter for bookdown or blogdown projects.
  • R formatters. posit.air-vscode and reditorsupport.r (through the styler package) both format R code. R uses REditorSupport.r as editor.defaultFormatter.
  • SCSS formatters. michelemelluso.code-beautifier and sibiraj-s.vscode-scss-formatter both format SCSS in R-Lecturer; [scss] picks the second.
  • Spelling and grammar. streetsidesoftware.code-spell-checker in both, znck.grammarly in R, valentjn.vscode-ltex in R-Lecturer. R-Lecturer also has a Grammarly setting without the extension.
  • LaTeX. james-yu.latex-workshop and mathematic.vscode-latex both provide LaTeX language support.
  • Markdown preview. shd101wyy.markdown-preview-enhanced duplicates much of the built-in preview with bierner.markdown-mermaid.
  • Not used for R work. zrachod.mono-snippets, sumneko.lua (unless you write Quarto filters) and ms-mssql.sql-bindings-vscode (comes with ms-mssql.mssql).

Installing them

With Settings Sync

With Settings Sync on, VS Code installs each profile’s extensions automatically when it downloads the profile on a new machine. Nothing else to do; see Profiles and Settings Sync.

Manual rebuild

install_extensions.ps1 reads a list with one extension id per line and installs it into a named profile:

  • It checks that code (the VS Code command-line tool) is on PATH.
  • It skips blank lines, lines starting with #, and extensions the profile already has (code --list-extensions --profile <name>).
  • It installs the rest with code --install-extension <id> --profile <name>.
  • At the end it lists the failures and exits with code 1 if there were any.

The VS Code command line only installs into a profile that already exists; for a missing one it reports Profile '<name>' not found. The script then opens VS Code once with code --profile <name>, which creates an empty profile, waits until the profile is there, and continues. If that does not work, create the profile in the Profiles editor (File → Preferences → Profiles) and run the script again. Use -Profile Default for the Default profile.

Put the script and the lists in one folder, then run, for example:

pwsh -File install_extensions.ps1 -Profile R -List extensions-R.txt
pwsh -File install_extensions.ps1 -Profile R-Lecturer

Without -List, the script uses extensions-<Profile>.txt next to itself. It needs PowerShell 7 (pwsh). github.copilot-chat now ships with VS Code, so the script reports it as built in or already installed.

Show the full file: install_extensions.ps1 
#Requires -Version 7.0
<#
.SYNOPSIS
    Install the VS Code extensions from a list file into a VS Code profile.

.DESCRIPTION
    Reads a text file with one extension id per line (as written by
    `code --list-extensions`), and installs every id that the profile does not
    have yet. Blank lines and lines starting with "#" are ignored. Failures are
    listed at the end and the script then exits with code 1.

    The VS Code CLI installs extensions only into a profile that already
    exists: `code --profile <name> --install-extension <id>` stops with
    "Profile '<name>' not found." The only CLI way to create a profile is to
    open a window with it (`code --profile <name>`), which creates an empty
    one. So when the profile is missing, the script does that once, waits until
    the CLI can see the profile, and then installs. If that does not work,
    create the profile in the Profiles editor (File > Preferences > Profiles)
    and run the script again.

    Use -Profile Default for the Default profile.

.EXAMPLE
    pwsh -File install_extensions.ps1
    Installs extensions-R.txt (next to the script) into the profile "R".

.EXAMPLE
    pwsh -File install_extensions.ps1 -Profile R -List extensions-R.txt

.EXAMPLE
    pwsh -File install_extensions.ps1 -Profile R-Lecturer
    Installs extensions-R-Lecturer.txt into the profile "R-Lecturer".
#>

[CmdletBinding()]
param(
    # Name of the VS Code profile. "Profile" is an alias so that the
    # automatic variable $PROFILE is not overwritten.
    [Alias('Profile')]
    [string] $ProfileName = 'R',

    # List of extension ids. Default: extensions-<Profile>.txt next to the
    # script.
    [string] $List,

    # Seconds to wait for a newly created profile to appear.
    [int] $CreateTimeout = 60
)

$ErrorActionPreference = 'Stop'

# --- Find the VS Code CLI ----------------------------------------------------
$codeCmd = Get-Command code -CommandType Application -ErrorAction SilentlyContinue |
    Select-Object -First 1
if (-not $codeCmd) {
    Write-Error ("The VS Code command 'code' is not on PATH. On Windows, tick 'Add to PATH' " +
        "in the installer; on macOS, run 'Shell Command: Install code command in PATH' " +
        "from the Command Palette. Then open a new terminal.")
    exit 2
}

function Invoke-Code {
    # Runs the VS Code CLI and returns its exit code and output (stdout and
    # stderr as text), without letting stderr stop the script.
    param([string[]] $Arguments)
    $ErrorActionPreference = 'Continue'
    $PSNativeCommandUseErrorActionPreference = $false
    $output = & $codeCmd.Source @Arguments 2>&1 | ForEach-Object { "$_" }
    [pscustomobject]@{
        ExitCode = $LASTEXITCODE
        Output   = @($output | Where-Object { $_ -ne '' })
    }
}

# --- Find the list -----------------------------------------------------------
if (-not $List) {
    $List = Join-Path $PSScriptRoot "extensions-$ProfileName.txt"
} elseif (-not (Test-Path -LiteralPath $List) -and -not [System.IO.Path]::IsPathRooted($List)) {
    # A relative path that is not in the current folder: try next to the script.
    $nextToScript = Join-Path $PSScriptRoot $List
    if (Test-Path -LiteralPath $nextToScript) { $List = $nextToScript }
}
if (-not (Test-Path -LiteralPath $List -PathType Leaf)) {
    Write-Error "List not found: $List"
    exit 2
}

$ids = Get-Content -LiteralPath $List -Encoding utf8 |
    ForEach-Object { $_.Trim() } |
    Where-Object { $_ -and -not $_.StartsWith('#') } |
    Sort-Object -Unique
if (-not $ids) {
    Write-Warning "No extension ids in $List."
    exit 0
}

# --- Make sure the profile exists ---------------------------------------------
# The Default profile is used when --profile is not given.
$profileArgs = if ($ProfileName -eq 'Default') { @() } else { @('--profile', $ProfileName) }

function Get-InstalledExtensions {
    $r = Invoke-Code (@('--list-extensions') + $profileArgs)
    if ($r.ExitCode -eq 0) { return , @($r.Output) }
    if ($r.Output -match 'not found') { return $null }   # profile does not exist
    throw "code --list-extensions failed (exit $($r.ExitCode)): $($r.Output -join ' ')"
}

$installed = Get-InstalledExtensions
if ($null -eq $installed) {
    Write-Host "Profile '$ProfileName' does not exist. Opening VS Code with it once to create it..."
    $null = Invoke-Code @('--new-window', '--profile', $ProfileName)
    $deadline = (Get-Date).AddSeconds($CreateTimeout)
    while ($null -eq $installed -and (Get-Date) -lt $deadline) {
        Start-Sleep -Seconds 2
        $installed = Get-InstalledExtensions
    }
    if ($null -eq $installed) {
        Write-Error ("Profile '$ProfileName' still does not exist. Create it in VS Code " +
            "(File > Preferences > Profiles > New Profile), then run this script again.")
        exit 2
    }
    Write-Host "Profile '$ProfileName' created."
}

# --- Install -------------------------------------------------------------------
Write-Host "Profile '$ProfileName': $($ids.Count) extension(s) in $(Split-Path $List -Leaf)."
$done = [System.Collections.Generic.List[string]]::new()
$skipped = [System.Collections.Generic.List[string]]::new()
$failed = [System.Collections.Generic.List[string]]::new()

foreach ($id in $ids) {
    # Extension ids are case-insensitive; -contains compares that way too.
    if ($installed -contains $id) {
        $skipped.Add($id)
        Write-Host "  skip     $id (already installed)"
        continue
    }
    $r = Invoke-Code (@('--install-extension', $id) + $profileArgs)
    $text = $r.Output -join ' '
    if ($text -match 'built-?in') {
        # E.g. GitHub Copilot Chat, which now ships with VS Code.
        $skipped.Add($id)
        Write-Host "  skip     $id (built into VS Code)"
    } elseif ($r.ExitCode -ne 0 -or $text -match 'Failed Installing|not found') {
        $failed.Add($id)
        Write-Host "  FAILED   $id : $text" -ForegroundColor Red
    } else {
        $done.Add($id)
        Write-Host "  install  $id"
    }
}

# --- Report ----------------------------------------------------------------------
Write-Host ''
Write-Host "Installed: $($done.Count). Skipped: $($skipped.Count). Failed: $($failed.Count)."
if ($failed.Count -gt 0) {
    Write-Host 'Failed extensions:' -ForegroundColor Red
    $failed | ForEach-Object { Write-Host "  $_" -ForegroundColor Red }
    exit 1
}
exit 0
