Profiles and Settings Sync

How I use VS Code profiles across machines, the Settings Sync gotcha that silently drops R settings, what Sync does not carry, and the Default and R-Lecturer profiles in full.
Modified

November 8, 2026

Profiles

A profile is a complete VS Code set-up: settings, keybindings, snippets, tasks, extensions and UI state. Each folder remembers which profile it was last opened with.

Profile Used for
R All daily R work, on every machine. The one documented on Settings, Keybindings and Extensions.
R-Lecturer Teaching. Kept close to what students get by default (light theme, default icons, Copilot mostly off), so what I show on the projector looks like their screen. See below.
Default Folders that are not R projects, and the place for application-wide settings (see below).

Other profiles (for Python and game development) are unrelated to R and not covered here.

Profiles do not inherit

A non-default profile’s settings.json replaces the Default one; it is not layered on top. Precedence is:

  1. VS Code’s built-in defaults,
  2. the active profile’s settings (Default or R or R-Lecturer, never a mix),
  3. the workspace settings (.vscode/settings.json in the project).

So every profile must contain everything it needs. That is why the R profile repeats most of the Default settings.

The one exception is application-scoped settings, such as update.mode and settingsSync.ignoredSettings. They apply to the whole VS Code installation and are read only from the Default profile. VS Code greys them out in other profiles; that is expected.

Where the files are

What Path
Default profile settings %APPDATA%\Code\User\settings.json
Other profiles %APPDATA%\Code\User\profiles\<profile id>\settings.json (also keybindings.json, tasks.json, snippets\)
Profile names, and which folder uses which profile %APPDATA%\Code\User\globalStorage\storage.json (VS Code rewrites it on exit: do not edit it while VS Code runs)

To move a folder to another profile, open it and pick the profile in the gear menu (bottom left). Delete obsolete profiles in the Profiles editor.

Settings Sync

Settings Sync keeps profiles, settings, keybindings, snippets, tasks, extensions and UI state the same on every machine where you sign in. Change a setting once, on any machine, and it travels. That only works if no machine-specific paths are in the synced files, which is the main design rule of this set-up (How the pieces fit).

The gotcha: some settings never sync

Sync silently skips three kinds of settings:

  • those marked machine (they only make sense on one computer),
  • those marked machine-overridable,
  • those flagged never to sync by their extension.

vscode-R marks several of its settings like that: r.consolePath, r.executablePath, r.consoleArgs, r.consoleSendDelay and r.plot.backend. The symptom is confusing: deleting such a setting syncs, but a new value never arrives on the other machine.

The fix is the settingsSync.ignoredSettings list. A leading - means “include this after all”:

"settingsSync.ignoredSettings": ["-r.consolePath", "-r.plot.backend"]
  • It must be in the Default profile (the download reads it from there) and in each synced profile (the upload reads it from the profile’s own file).
  • After changing the list, the receiving machine may need Settings Sync: Sync Now twice.
  • To see what was actually uploaded: Settings Sync: Show Synced Data, or %APPDATA%\Code\User\sync\<profile id>\settings\lastSyncsettings.json.

The two settings it opts back in are safe to sync because they hold no paths: r.consolePath is just "radian" (found on PATH), and r.plot.backend is "httpgd".

What Settings Sync does not carry

Not synced Where it lives How I keep it in step
R, Rtools, Python, radian, Quarto, R packages installed per machine Install, in order, the same versions everywhere
PATH and environment variables Windows the PATH rules
Task scripts %USERPROFILE%\.vscode-scripts\ copied by hand (Snippets and tasks)
.Rprofile Documents\.Rprofile OneDrive shares the Documents folder (Outside VS Code)
PowerShell profiles Documents\PowerShell\ OneDrive, as above
Which folder uses which profile storage.json set per machine (gear menu)
