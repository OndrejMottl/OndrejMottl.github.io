Profiles and Settings Sync

How I use VS Code profiles across machines, the Settings Sync gotcha that drops R settings, what Sync does not carry, and my Default and R-Lecturer profiles.
Modified

November 9, 2026

Profiles

A profile is a complete VS Code set-up: settings, keybindings, snippets, tasks, extensions and UI state. Each folder remembers which profile it was last opened with.

Profile Used for
R All daily R work, on every machine. The one documented on Settings, Keybindings and Extensions.
R-Lecturer Teaching: VS Code’s defaults plus what is needed to run R. See below.
Default Folders that are not R projects, and the place for application-wide settings (see below).

My other profiles are unrelated to R and not covered here.

Profiles do not inherit

A non-default profile’s settings.json replaces the Default one; it is not layered on top. Precedence is:

  1. VS Code’s built-in defaults,
  2. the active profile’s settings (Default or R or R-Lecturer, never a mix),
  3. the workspace settings (.vscode/settings.json in the project).

So every profile must contain everything it needs. That is why the R profile repeats most of the Default settings.

The one exception is application-scoped settings, such as update.mode and settingsSync.ignoredSettings. They apply to the whole VS Code installation and are read only from the Default profile; other profiles show them greyed out.

Where the files are

What Path
Default profile settings %APPDATA%\Code\User\settings.json
Other profiles %APPDATA%\Code\User\profiles\<profile id>\settings.json (also keybindings.json, tasks.json, snippets\)
Profile names, and which folder uses which profile %APPDATA%\Code\User\globalStorage\storage.json

To move a folder to another profile, open it and pick the profile in the gear menu (bottom left).

Settings Sync

Settings Sync keeps profiles, settings, keybindings, snippets, tasks, extensions and UI state the same on every machine where you sign in. Change a setting once, on any machine, and it travels. That only works if the synced files contain no machine-specific paths (How the pieces fit).

The gotcha: some settings never sync

Sync silently skips three kinds of settings:

  • those marked machine (they only make sense on one computer),
  • those marked machine-overridable,
  • those flagged never to sync by their extension.

vscode-R marks several of its settings like that: r.consolePath, r.executablePath, r.consoleArgs, r.consoleSendDelay and r.plot.backend.

The fix is the settingsSync.ignoredSettings list. A leading - means “include this after all”:

"settingsSync.ignoredSettings": ["-r.consolePath", "-r.plot.backend"]
  • It must be in the Default profile, where VS Code reads application-scoped settings. I keep the same line in each synced profile as well.
  • To see what was uploaded: Settings Sync: Show Synced Data.

The two settings it opts back in are safe to sync because they hold no paths: r.consolePath is just "radian" (found on PATH), and r.plot.backend is "httpgd".

What Settings Sync does not carry

Not synced Where it lives How I keep it in step
R, Rtools, Python, radian, Quarto, R packages installed per machine Install, in order, the same versions everywhere
PATH and environment variables Windows the PATH rules
Task scripts %USERPROFILE%\.vscode-scripts\ copied by hand (Snippets and tasks)
.Rprofile Documents\.Rprofile OneDrive shares the Documents folder (Outside VS Code)
PowerShell profiles Documents\PowerShell\ OneDrive, as above
Which folder uses which profile storage.json set per machine (gear menu)

The R-Lecturer profile

My teaching profile keeps VS Code’s defaults and adds only what is needed to run R:

  • radian as the R console and httpgd for plots (r.consolePath, r.bracketedPaste, r.plot.backend; needs the httpgd R package), with the same settingsSync.ignoredSettings line as R;
  • the Light Modern theme, for the projector;
  • no Copilot completions;
  • Quarto previews in the browser, and the visual editor wraps at 80 columns and spell-checks in British English.

Its only extensions are vscode-R (reditorsupport.r, reditorsupport.r-syntax) and Quarto (quarto.quarto); Copilot Chat ships with VS Code. It has no keybindings, tasks or snippets of its own.

Show the full file: R-Lecturer settings.json 
{
  // Teaching profile: VS Code defaults plus what is needed to run R.

  // R: radian on PATH as the console, plots in the httpgd viewer
  // (needs the httpgd R package).
  "r.consolePath": "radian",
  "r.bracketedPaste": true,
  "r.plot.backend": "httpgd",
  // Settings Sync skips these two by default; "-" makes it sync them.
  "settingsSync.ignoredSettings": ["-r.consolePath", "-r.plot.backend"],

  // Light theme for the projector.
  "workbench.colorTheme": "Light Modern",

  // No Copilot completions while teaching.
  "github.copilot.enable": {
    "*": false
  },

  // Quarto: preview in the browser; visual editor wraps at 80 columns.
  "quarto.render.previewType": "external",
  "quarto.render.previewReveal": false,
  "quarto.visualEditor.markdownWrap": "column",
  "quarto.visualEditor.markdownWrapColumn": 80,
  "quarto.visualEditor.spelling": true,
  "quarto.visualEditor.spellingDictionary": "en_GB"
}
