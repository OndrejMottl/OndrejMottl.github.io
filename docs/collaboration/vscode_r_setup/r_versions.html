R versions

Switch the R version for the whole machine with rig, or pin one project to an older version, with the R Version Switcher extension or by hand.
Modified

November 8, 2026

How VS Code finds R

Nothing in my synced settings names an R version or a path:

  • r.consolePath is "radian", found on PATH.
  • r.executablePath is not set. vscode-R then uses R.exe on PATH, which is rig’s shortcut in C:\Program Files\R\bin. Failing that, it reads the Windows registry (HKLM\Software\R-Core\R\InstallPath).
  • radian looks for R the same way: --r-binary, R_BINARY or R_HOME if set, then R on PATH, then the registry.

Result: the R version is whatever rig default says on that machine. The settings stay identical everywhere, which is what lets Settings Sync carry them.

Switch R for the whole machine

rig list              # installed versions; * marks the default
rig add release       # install the newest release (or: rig add 4.5)
rig default 4.6.2     # use it everywhere

Then open a new R terminal. No VS Code change is needed. Remember that a new R version starts with an empty package library: install the R packages for it.

Pin one project to a version

Sometimes a project needs an older R, for example one whose renv.lock was made with R 4.5.1. The pin goes into that project’s workspace settings, .vscode/settings.json, which override the profile.

With the R Version Switcher extension

I wrote (well, vibe-coded) a small extension for this: R Version Switcher. It works with rig and the R extension:

Command What it does
R: Switch Version Pick an installed R version for this workspace. The list marks the current one, the system default and the one in renv.lock.
R: Use R Version from renv.lock Switch to the version recorded in renv.lock; offers to install it (or the newest patch of the same minor version) if it is missing.
R: Show Current Version The workspace’s R version and path, and whether the path is valid.
R: Add Version / R: Remove Version rig add / rig rm, run as a VS Code task so you see the output.
R: Set System Default Version rig default, without touching the workspace.
R: Install Rtools Installs the Rtools versions your R versions need but do not have.

A status bar item shows the workspace’s R version and turns yellow when it differs from renv.lock. Click it to switch. That pairs well with the project template, which uses renv.

As the extension’s README says: it was written by an AI coding assistant and can install and remove R versions, so read what a command will do before you confirm it.

Restart the R terminal after switching.

By hand

First, once per machine, create the version-named shortcuts:

rig system make-links   # creates R-4.6.2.exe, R-4.5.1.exe, ... in C:\Program Files\R\bin

Then in the project’s .vscode/settings.json:

{
  "r.executablePath": "R-4.5.1",
  "r.consoleArgs": ["--r-binary=R-4.5.1"]
}
  • r.executablePath is the R that vscode-R uses for the language server, help and the workspace viewer.
  • r.consoleArgs is passed to radian. --r-binary makes radian start that R. radian does not save or restore the workspace by default (--save / --restore-data turn that on), so --no-save --no-restore are not needed.
  • R-4.5.1 is found on PATH, so the file contains no user name and no install path. It works on every machine that has R 4.5.1 through rig, so the file can be committed.
  • A full path such as C:\\Program Files\\R\\R-4.5.1\\bin\\R.exe also works and contains no user name, but it is Windows-only.

To check which R a terminal really runs: R.version.string in the console, or radian --r-binary=R-4.5.1 --version in PowerShell.

Old setting names

Older guides (and older versions of tools) write r.rpath.windows, r.rterm.windows and r.rterm.option. vscode-R 3.x renamed them to r.executablePath, r.consolePath and r.consoleArgs (full list). The old names still work but VS Code shows them struck through.
