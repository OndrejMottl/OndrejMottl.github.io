Settings reference

The settings of my R profile: what each one does, grouped as in the file.
Modified

November 8, 2026

This page goes through the settings.json of my R profile, the one profile I use for all R work. It is synced between my machines with Settings Sync. Profiles do not inherit settings from the Default profile, so copying this file into a new profile gives the same set-up. The exceptions are a few application-wide settings, which VS Code always reads from the Default profile (see settingsSync.ignoredSettings below). How profiles and sync fit together is on Profiles and Settings Sync.

“(default)” in a row means the value is the same as the VS Code or extension default.

Window and workbench

Setting Value What it does
workbench.panel.defaultLocation "right" Opens the panel (terminal, Problems, Output) to the right of the editor instead of below it.
security.workspace.trust.untrustedFiles "open" Opens files from outside a trusted workspace without asking.
zenMode.centerLayout true Centres the editor in Zen mode (default).
window.commandCenter true Shows the Command Center search box in the title bar (default).
workbench.iconTheme "vscode-icons" Uses the file icon theme from the vscode-icons extension.
vsicons.dontShowNewVersionMessage true Stops vscode-icons from showing a “new version” message after each update.
workbench.list.openMode "doubleClick" In the Explorer and other lists, a single click selects an item and a double click opens it.
workbench.colorTheme "Visual Studio Dark" Uses the built-in “Dark (Visual Studio)” colour theme.
workbench.editor.pinnedTabsOnSeparateRow true Shows pinned tabs on their own row above the other tabs.
workbench.editor.wrapTabs true Wraps tabs onto more rows instead of scrolling them sideways.
window.title "${rootName}" Shows only the workspace or folder name in the window title.

Terminal

Setting Value What it does
terminal.integrated.cursorStyle "underline" Draws the terminal cursor as an underline.
terminal.integrated.cursorBlinking true Makes the terminal cursor blink.
terminal.integrated.defaultProfile.windows "R Terminal" Every new terminal uses the “R Terminal” profile.
terminal.integrated.fontWeightBold "normal" Draws bold terminal text in normal weight.

The “R Terminal” profile comes from the vscode-R extension (REditorSupport.r) and starts the R console set in r.consolePath (radian), so a new terminal opens an R session; PowerShell is still available from the drop-down next to +. The terminal keybindings are on Keybindings.

Editor

Setting Value What it does
editor.stickyScroll.enabled true Pins the headers of the current scopes (functions, headings, chunks) at the top of the editor while scrolling (default).
editor.unicodeHighlight.nonBasicASCII false Does not highlight characters outside basic ASCII.
editor.tabSize 2 One indentation level is 2 spaces.
editor.defaultFormatter "REditorSupport.r" Uses vscode-R as the formatter for every language without its own override.
editor.inlineSuggest.enabled true Allows inline (ghost-text) suggestions in the editor (default).
editor.guides.bracketPairs "active" Draws a vertical guide only for the bracket pair the cursor is in.
editor.rulers [80] Draws a vertical line at column 80.
editor.accessibilitySupport "off" Turns off the screen-reader optimised mode instead of detecting it automatically.

Minimap

Setting Value What it does
editor.minimap.autohide "mouseover" Hides the minimap until the mouse is over it.
editor.minimap.maxColumn 80 Draws at most 80 columns of each line in the minimap.
editor.minimap.renderCharacters false Draws blocks instead of tiny characters.
editor.minimap.scale 2 Draws the minimap content at twice the normal size.

editor.defaultFormatter is the formatter for Format Document (Shift+Alt+F) in every language that has no override. vscode-R formats R code through the R language server (the languageserver R package, which uses styler), so those packages have to be installed in each R version I use. Format on save is not turned on, so formatting only happens when I ask for it.

The vscode-R formatter can only format R, so the other languages get their own formatter in Language-specific formatters.

R language

These settings belong to the vscode-R extension (REditorSupport.r), except r.debugger.timeouts.startup, which belongs to the R Debugger extension (rdebugger.r-debugger).

Setting Value What it does
r.alwaysUseActiveTerminal true Sends code to the active terminal instead of a terminal vscode-R created itself.
r.bracketedPaste true Sends code to the console in bracketed paste mode.
r.consolePath "radian" The R console started in R terminals.
settingsSync.ignoredSettings ["-r.consolePath", "-r.plot.backend"] Settings that Settings Sync skips; a leading - makes it sync a setting it would skip by default.
r.source.focus "editor" Keeps the focus in the editor after sourcing or running code.
r.sessionWatcher true Connects the R session to VS Code: workspace viewer, plot viewer, data viewer, help (default).
r.plot.backend "httpgd" Shows plots in the httpgd plot viewer inside VS Code.
r.plot.defaults.fullWindowMode true Opens the httpgd plot viewer in full-window mode, with the plot filling the viewer.
r.lsp.debug true Writes debug output of the R language server to its Output channel.
r.lsp.diagnostics true Shows the language server’s lint diagnostics (from lintr) in the editor (default).
r.debugger.timeouts.startup 20000 How long (ms) the R Debugger waits for R to start.

R console: radian on PATH, no R path

r.consolePath is the bare program name "radian", found on PATH (see Installation), and r.executablePath is not set, so the file holds no machine-specific paths. vscode-R then uses the R found on PATH, which with rig is the rig default version; how it looks for R, and how to pin a version for one project, is on R versions with rig.

Settings Sync and the two R settings

Settings Sync skips settings that are scoped machine or machine-overridable, or marked ignoreSync. Two settings this set-up depends on are affected: r.consolePath is machine-overridable, and r.plot.backend is ignoreSync. Without the line below, a new machine would get the rest of the profile but not radian and not httpgd.

settingsSync.ignoredSettings is the list of settings Sync should skip. A leading - does the opposite: it opts a setting back in. So ["-r.consolePath", "-r.plot.backend"] makes Sync carry both.

settingsSync.ignoredSettings itself is an application-scoped setting: VS Code reads it from the Default profile only. The same line therefore also has to be in the Default profile’s settings.json, otherwise it has no effect. See Profiles and Settings Sync.

Plots: httpgd

With r.plot.backend: "httpgd", plots open in a VS Code tab that resizes the plot with the window and keeps a plot history. It needs the httpgd R package in every R version I use; with rig, each version has its own library, so I install it per version (R versions with rig).

GitHub Copilot

Setting Value What it does
github.copilot.enable on for *, off for plaintext and scminput Turns Copilot inline suggestions on or off per language.
github.copilot.editor.enableAutoCompletions false Copilot does not show completions automatically while typing.
github.copilot.nextEditSuggestions.enabled true Turns on Next Edit Suggestions: Copilot proposes the next change based on recent edits.
github.copilot.chat.commitMessageGeneration.instructions file .github/commit-instructions.md Extra instructions Copilot follows when generating a commit message. 
"github.copilot.enable": {
  "*": true,
  "plaintext": false,
  "markdown": true,
  "scminput": false,
  "quarto": true,
  "r": true
},

"*": true turns Copilot on everywhere, and the other keys are exceptions or confirmations. plaintext (.txt files) and scminput (the commit message box in Source Control) are off. markdown, quarto and r are on explicitly, which * already covers; listing them keeps them on if * is switched off. The keys are VS Code language ids, which are lower-case.

With github.copilot.editor.enableAutoCompletions: false and github.copilot.nextEditSuggestions.enabled: true, Copilot does not complete code as I type. Instead it suggests edits: after a change it proposes the matching next change nearby (for example, renaming the other uses of a variable), which I accept with Tab. When I do want an inline suggestion, Ctrl+Alt+I asks for one on demand (Keybindings).

The Generate Commit Message button in Source Control reads .github/commit-instructions.md from the root of the open repository and follows it. The path is relative, so each repository can have its own rules; if the file does not exist, Copilot uses its default style. My Project_template ships this file, so every project made from it has the same commit conventions.

Spell check

These belong to Code Spell Checker (streetsidesoftware.code-spell-checker).

Setting Value What it does
cSpell.userWords list of words, see below Words accepted as correct in every file and project.
cSpell.language "en-GB,cs" Languages to check spelling in.

The user words are:

  • R packages and R terms: dplyr, purrr, tarchetypes, tibble, tidyverse, hmsc, xlim, ylim, agelim, timestep.
  • Projects and databases: vegvault, Neotoma.
  • Names and identifiers: Ondřej, Mottl, ORCID.

cSpell.language takes a comma-separated list of language codes. British English is built into Code Spell Checker. Czech is not: it needs the separate Czech dictionary extension (streetsidesoftware.code-spell-checker-czech, see Extensions), and its code is cs (the ISO code), not cz (the country). A word counts as correct if it is in any of the listed languages.

claudeCode.hideOnboarding true Hides the onboarding / welcome content in the Claude Code extension.

"chat.tools.terminal.autoApprove": {
  "Copy-Item": true,
  "New-Item": true,
  "Test-Path": true,
  "robocopy": true,
  "quarto": true
},
"chat.tools.urls.autoApprove": {
  "https://cran.r-project.org": true,
  "https://besjournals.onlinelibrary.wiley.com": {
    "approveRequest": true,
    "approveResponse": false
  }
},

In agent mode, the chat asks before it runs a terminal command. Commands listed in chat.tools.terminal.autoApprove with true run without asking. Here that is three PowerShell commands to copy files, create files and folders, and test whether a path exists (Copy-Item, New-Item, Test-Path), robocopy, and quarto. A plain name matches the command whatever arguments follow it, so this includes robocopy /MIR and quarto render.

chat.tools.urls.autoApprove works the same way for web fetches, with two steps per site: sending the request and using the response. I let the agent fetch CRAN pages freely; for the British Ecological Society journals site on Wiley it fetches without asking but asks before using what it fetched.

The YAML extension normally detects a schema for a YAML file from its file name (via the JSON Schema Store) and uses it for validation and completion. This list turns that automatic detection off for Docker Compose files and for GitHub, Gitea and Forgejo workflow files.
